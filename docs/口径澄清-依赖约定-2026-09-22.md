## 一、原文与事实

>
> 项目**刻意只用 Python 标准库**。这是「设备侧零部署 + CI 轻量」的一部分，
> 引入依赖会被打回。`requirements.txt` 里只有开发期的可选工具。

### 事实（`requirements.txt`）

```

```

## 二、对不上的地方有三处（不止「pip」那一处）

| # | 原文说 | 事实是 |
|---|---|---|
| 1 | 「**不要 pip install 任何东西**」 | CI 里 `pip install` 了 **pyyaml 和 coverage** 两样 |
| 2 | 「`requirements.txt` 里只有**开发期的可选**工具」 | **`coverage` 根本不在 `requirements.txt` 里**（CI 单独装）—— 这句把工具链说漏了一个 |
| 3 | 同上，暗示 pyyaml 只是「可选」 | **它不完全是可选的**：`load_case()` **读 YAML 时必须有它**，没装只能走 JSON 用例，`cases/*.yaml` 读不回来（见 `requirements.txt` 里的注释） |

**第 1 条的实际代价已经发生了** —— B 因为不知道该听哪句而卡住，专门来问。

## 三、建议改成这样说（可直接替换第 67-70 行）

```markdown
### （一）核心能力零第三方依赖（不是「不许 pip install」）

**约束对象是「核心能力」，不是「所有 pip 命令」。** 原表述写成「不要
`pip install` 任何东西」，与本仓库 CI 自己的 `pip install -r requirements.txt`
与 `pip install coverage` 直接打架（2026-09-22 B 就卡在这条上）。

分三层看：

| 层 | 内容 | 规则 |
|---|---|---|
| **核心能力** | `hdc` / `layout` / `matcher` / `driver` / `runner` / `report` / `sim` | **零第三方**。引一个进来就算违规、要打回 |
| **DSL 序列化后端** | `pyyaml` | 写可退化 JSON；**读 YAML 必须有它**（细节见 `requirements.txt` 注释） |
| **工具链** | `coverage`、`pyyaml` | CI 与本地开发装，**不进设备侧、不进分发产物** |

**所以**：`requirements.txt` 里可以有东西、CI 会装它 —— 这不违反约定；
**在核心模块里 `import` 第三方包才违反**。

> 这条的本意是防「随手加个 requests / numpy，把设备侧部署搞复杂」。
> 意图是对的，只是表述太绝对。按层表述后既保住了约束力，也和 CI 自洽。
```

---

## 四、为什么这么定（决策依据）

定这条不用开会讨论，**照事实对齐即可**：

1. **事实优先于文字** —— CI 一直在装 pyyaml 和 coverage，
   说明「零 pip」从来不是真的。文字要向事实看齐，不是反过来。
2. **看约定要防什么** —— 防的是「核心能力膨胀出第三方依赖」，
   不是「禁止一切 pip 命令」。分层表述保住了意图，还更可执行。
3. **看有没有人被卡住** —— B 卡了一次，这就是表述不清的实锤代价。

**不需要争论的是**：要不要允许 pyyaml。
**它已经在用了**（`requirements.txt` 声明、CI 安装、受管环境已装 6.0.3），
争这个没有意义。**要定的只是「话该怎么说」。**

## 五、给 A / B 的可执行判据（不必等文档更新）

在文档改定之前，按这一条办事就够了：

> **核心模块（`ohauto/` 下的 hdc / layout / matcher / driver / runner /
> report / sim）里不许 `import` 任何第三方包。**
> **工具链（`tools/`、CI、测试辅助）可以用，装的时候走 `requirements.txt`，
> 需要门禁专用的再单独装（如 `coverage`）。**

具体到 pyyaml：

| 你的场景 | 要不要装 |
|---|---|
| 核心能力开发 / 只跑 `tests/` | **不用**（测试全用 JSON 或已装） |
| 要读 `examples/cases/*.yaml` | **要**（`load_case()` 读 YAML 必须它） |
| 只是写用例（`dump_case()`） | 不用，没有它会自动写 JSON |
