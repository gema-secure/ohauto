## 三、对外接口（分工卡契约，W2 冻结范围内）

```python
from ohauto import LocatorManager, LocateResult, RepairReport

lm = LocatorManager(vision=HybridLocator(provider=...))   # vision 可选

spec = lm.register(target, page, page_signature='')  # 可显式注册，也可 locate 时自动
r = lm.locate(target, page, page_signature='', image_path=None, screen_size=(0,0))
    # -> LocateResult(rect, channel, confidence, health, locator_id, level, ...)
    #    channel: 'tree' | 'vision' | 'hybrid' | 'coordinate'
    #    全链路落空返回 None（内部已自动记失败）

lm.record_locator_failure(locator_id, reason)   # B 执行失败回写（幂等）
lm.repair_locators(page_signature, page=None, force=False)  # -> RepairReport
lm.all_health()   # 健康度快照，报告/答辩直接用
```

## 四、A3 自愈的验收口径（答辩演示脚本）

1. 构造 5 控件页面，注册 5 个定位器；
2. **人为改掉全部 5 个 id** → 降级链 L3（层级路径+类型）全部接住，
   成功率 5/5 = 100% ≥ 80%（`test_five_renamed_ids_auto_recover`）；
3. 更狠的：id 换掉 + 结构变掉（控件挪进新容器链）→ 降级链全灭 →
   坐标兜底记失败告警 → **连续失败到阈值自动触发自愈** →
   第 4 次调用起新一代定位器直连命中（`test_repair_triggers_after_threshold_without_manual_action`）；
4. 自愈无法安全定人时如实报失败、不改定位器（`test_repair_report_lists_failures_when_ambiguous`）。

## 五、两点设计取舍的说明（请 B/C 过目）

1. **坐标兜底记失败不记成功**：L5 兜底返回的坐标只是救急点，健康度上按失败记账，
   否则"坐标兜底永远成功"会掩盖连续失败、自愈永远不触发（测试全绿但结论是假的，
   分工卡第一章第（六）节的教训）。B 回写失败记录时请以这个语义为准。
2. **treesum 的 `enabled` 不作为保留条件**：真机树上几乎全部节点 enabled=true，
   按卡片字面实现压缩率恒为 0。`keep_enabled=True` 可切回字面行为，详见模块 docstring。
