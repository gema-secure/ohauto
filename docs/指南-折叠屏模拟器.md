# 折叠屏模拟器操作指南

本文说明如何使用 DevEco 模拟器实例（Emulator 26.0.0.400）执行折叠形态的
跨形态测试：安装镜像、启动实例、切换折叠态、导出控件树并执行差异比对。
模拟器实例由 `tools/emulator_cli.py` 管理，不依赖 DevEco 图形界面。

术语约定：本文中的 Mate X7 等均为 DevEco 模拟器实例，不是物理真机；
两者的测试结论分别记录，不互相替代。

## 一、环境准备

### 1. 接受协议

```bash
python tools/emulator_cli.py accept --yes
```

验收：`status` 中协议显示为已接受。协议原文位于
`<DevEco>\tools\emulator\agreement\`，状态记录在
`%LOCALAPPDATA%\Huawei\Emulator26.0\.emu_config`。

### 2. 下载镜像

折叠设备的镜像归在 `phone` 类目下。Mate X7 的 `deviceType` 是 `foldable`，
但其 `imageDir` 指向 `system-image/HarmonyOS-7.0.0/phone_all_x86/`——
下载镜像时 `-deviceType` 必须传 `phone`，按字面传 `foldable` 会下载错误镜像。
判断依据是实例的 `imageDir` 字段（`lists.json` 或 `-list -details`），
不是 `deviceType`。

```bash
# phone / foldable / triplefold / widefold 四类设备共用同一份 phone_all_x86 镜像
python tools/emulator_cli.py install phone --os-version "HarmonyOS 7.0.0(26.0.0)"
```

注意事项：

- 已创建的实例锁死系统版本。若现有实例为 HarmonyOS 7.0.0，必须下载同版本镜像；
  下载最小版本需要重建实例。工具的 `install` 默认策略是最小版，
  对已有实例的场景应显式传 `--os-version`。
- `-install` 是交互式命令，不提供 stdin 时会把 EOF 当作拒绝而中止，
  且退出码为 0、不报错。`emulator_cli.py` 已内置应答处理。
- 下载进度的判据是镜像目录中 `.zip` 文件体积是否增长；
  `-imageList` 在解压注册前始终显示 `downloaded=false`，不能作为判据。
- 平板等其他形态依次下载 `tablet` 等类目；一次只下载一个镜像（单个 1–2 GB）。

## 二、启动实例

### 由常驻后台任务持有启动进程

`Emulator.exe -start` 是前台常驻进程。启动方式必须满足：调用方进程保持存活、
不用 `subprocess` 等待超时、不使用分离进程标志。否则会出现两类静默失败：
等待超时会连同模拟器一起终止；分离启动会无报错退出
（日志仅剩 Hypervisor 初始化一行）。

正确方式是在常驻的后台任务中执行：

```bash
"<DevEco>\tools\emulator\Emulator.exe" -start "Mate X7" > emu.log 2>&1
```

或使用封装命令：

```bash
python tools/emulator_cli.py start "Mate X7" [--no-window] [--skip-check]
```

冷启动约 40–60 秒后设备出现在 `hdc list targets`（`127.0.0.1:5555`）。
内存是主要约束：单个实例约占 4 GB，同时只运行一个实例。

### 启动失败的处置

| 现象 | 处置 |
|---|---|
| 提示协议未接受 | 重新执行第 1 步 |
| 提示镜像不存在 | 重新执行镜像下载 |
| 卡在启动画面 | 首次冷启动需要数分钟，属正常 |
| 内存不足 | 关闭占用内存的应用；或仅使用物理真机 |
| 直接闪退 | 用 `status` 查看状态，日志在实例目录下 |

## 三、折叠态切换与验证

Mate X7 支持三种折叠态：`open` / `half-open` / `close`
（三折叠机型 `triplefold` 支持 9 种，见 `emulator_cli.py fold --show-states`）。

### 判定折叠态是否生效

折叠态切换改变的是屏幕电源状态，不是分辨率。两块屏的分辨率恒定：
内屏 2416×2210，外屏 1080×2444。判定必须读取电源状态：

```bash
hdc shell hidumper -s RenderService -a screen
```

| 折叠态 | 内屏 | 外屏 |
|---|---|---|
| `open` / `half-open` | 点亮 | 关闭 |
| `close` | 关闭 | 点亮 |

另外 `-list -details` 的 `isRunning` 恒为 `false`，不能用于判断实例存活；
存活判据只有 `hdc list targets` 加 `hdc shell echo`。

### 切换后等待界面重绘

`-foldedState` 返回成功不代表界面已完成重绘。切换后立即采集有约三分之一
概率得到空树（仅一个无子节点的根节点），直接比对会产生"全部元素缺失"
的假差异。采集侧必须重试并校验元素数下限（该逻辑已固化在
`tools/crossform_run.py` 的 `capture_online`）：

```python
for attempt in range(1, retries + 1):
    time.sleep(_FOLD_SETTLE_SEC if attempt == 1
               else _FOLD_SETTLE_SEC * attempt)   # 3s / 6s / 9s / 12s
    ...
    if sum(1 for _ in root.walk()) >= min_elements:   # 默认 3
        return capture
```

元素数下限取 3 而非 1：真实界面不可能只有一两个元素，
该下限是低成本的空树哨兵。

### 一键端到端验证

```bash
python tools/verify_emulator.py              # 全流程（设备已在线则复用）
python tools/verify_emulator.py --status-only
python tools/verify_emulator.py --screens-only
python tools/verify_emulator.py --no-window  # 隐藏窗口；无显示的 CI 环境不可用
python tools/verify_emulator.py --skip-fold  # 非折叠设备
```

判定逻辑：要求不同折叠态检出不同的点亮屏幕尺寸；
若三种折叠态尺寸一致，则判定为需人工确认，不会误报通过。

## 四、跨形态差异比对

### 执行

```bash
# 模拟器实例（需模拟器在线；采集 open / close 两态并比对）
python tools/crossform_run.py --device "Mate X7" ^
    --baseline open --target close --stem matex7

# 离线（无需设备，用固定页面验证判据）
python tools/crossform_run.py --offline --offline-page static_fixed ^
    --baseline close --target open --out out/crossform/target --stem target

# 对照实验：仅按 id 匹配
python tools/crossform_run.py --offline --offline-page static_fixed ^
    --baseline close --target open --only-id --out out/crossform/onlyid --stem onlyid
```

参考结果（Mate X7 实例，open → close）：缺失 11 / 越界 0 / 不可达 0 / 溢出 1。
报告的解读见 `tests/fixtures/crossform/README-matex7-desktop.md`——
「检出元素消失」是引擎对两态差异的客观记录，不等于应用缺陷结论。

### 退出码

| 退出码 | 含义 |
|---:|---|
| 0 | 无高严重度差异 |
| 2 | 检出高严重度差异（MISSING / UNREACHABLE） |

门禁判据直接使用引擎的 `has_high()`，不在外部另立高严重度类型清单，
避免两套定义漂移导致报告与门禁结论不一致。

### 产物

| 文件 | 用途 |
|---|---|
| `crossform.md` | 人读差异报告 |
| `crossform.html` | 带样式版本（自包含 CSS） |
| `crossform.json` | 机器可读，供 CI 与二次分析 |
| `run.json` | 运行元信息（含 `has_high`，供门禁读取） |

### 差异判据

| 判据 | 含义 | 默认严重度 |
|---|---|---|
| `MISSING` | 同一身份的元素在目标形态中不存在 | 高 |
| `OUT_OF_SCREEN` | bounds 超出屏幕边界（按裁切像素分级） | 中 |
| `UNREACHABLE` | 中心点落在挖孔区，或裁切后可见面积不足原面积 1% | 高 |
| `OVERFLOW` | bounds 超出父容器 bounds | 中 |

### 元素身份策略

跨形态比对不能用坐标认元素（坐标必然变化）。元素身份按三级降级：

```
id:xxx  →  tp:type|text  →  hp:type@父容器类型链
```

`hp:` 级是兜底：id 与文本都不可用时，按元素类型加父容器类型链定位。
实测中该级承担了部分仅靠 id 无法认出的元素。

## 五、采集 hidumper 原始数据（可选，供解析器开发）

```bash
hdc shell hidumper -s WindowManagerService -a '-a'         > emu_wms_windows.txt
hdc shell 'hidumper -s DisplayManagerService -a "-s -a"'   > emu_dms_screens.txt
hdc shell 'hidumper -s DisplayManagerService -a "-d -a"'   > emu_dms_displays.txt
```

注意 `-s WindowManagerService -a -a` 参数组合会返回
`arguments are illegal`，正确参数以上述命令为准。

## 六、释放资源

实例运行约占 4 GB 内存，用完后停止：

```bash
python tools/emulator_cli.py stop "Mate X7"
python tools/emulator_cli.py status | grep "Mate X7"
# 期望：running=false
```

启动时持有的常驻进程在 stop 后仍显示存活，属正常现象——它是持有者
而非模拟器本身。以 `running=false` 且 `hdc list targets` 为空作为已释放的判据。
