## 一句话结论

你的幂等闸把执行器的回写**全部误判成了重复记账**：连续失败永远停在 1，
自愈阈值永远够不着，**自愈在生产链路上一次都不会触发**。

## 根因（行号级证据）

`locator.py:547` 的幂等键：

```python
if self._fail_seq.get(locator_id) == self._locate_seq:   # 547 行
    self._log(f'{locator_id} 同一次定位失败的重复记账，已去重: {reason}')
    return False
```

- `_locate_seq` **只在 `locate()` 里推进**（283 行：`self._locate_seq += 1`）。
- 执行器（runner）走 matcher/layout 定位，**从不调 `locate()`** → 代次恒为 0。
- 于是第 1 次回写后 `_fail_seq[lid] = 0`，第 2 次起 `0 == 0` 恒成立 →
  **全部被去重丢弃**，`consecutive_failures` 永远是 1（`failure_threshold` 达不到）。

你自己在 534 行的 docstring 里写的是「下一次 locate() 代次推进后照常记账」——
但执行器路径**没有下一次 locate()**。设计假设与生产链路对不上。

## 修法（最小改动，C 已把管道侧备好）

`record_locator_failure` / `_count_failure` 加一个**可选**参数 `attempt`
（执行器侧的执行尝试序号，单调递增，由 C 的 runner 维护并传出）：

```python
def record_locator_failure(self, locator_id: str, reason: str,
                           attempt: int = None) -> None:
    self._count_failure(locator_id, reason, attempt)

def _count_failure(self, locator_id: str, reason: str,
                   attempt: int = None) -> bool:
    h = self._health.get(locator_id)
    if h is None:
        return False
    # 幂等键：执行器给了 attempt 就用它（一次执行尝试 = 一次记账）；
    # 没给（内部 locate 路径）保持旧代次闸，行为完全不变。
    seq = attempt if attempt is not None else self._locate_seq
    if self._fail_seq.get(locator_id) == seq:
        self._log(f'{locator_id} 同一次定位失败的重复记账，已去重: {reason}')
        return False
    self._fail_seq[locator_id] = seq
    h.attempts += 1
    h.consecutive_failures += 1
    ...
```

### 为什么这样改

- **内部 `locate()` 路径零变化**（不传 attempt，走旧代次闸）——你现有
  21+ 项测试不用动。
- **执行器路径的语义**：runner 的 `_report_locator_failure` 每个失败步骤
  只调一次（「定案失败只调一次」的契约，B/C 侧已遵守），每次调用自带
  新的 attempt → 每次都该计入。连续失败 = 连续多次执行失败，正是
  自愈想要的输入。
- **幂等仍成立**：如果有人拿同一个 attempt 重复回写，照样被去重。
