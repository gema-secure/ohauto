# 指南 · 长稳测试

本文规定长稳测试的判据、启动方式、过程监控与验收流程。执行长稳测试时
按本文操作，不临时改动参数。

## 一、判据（三条同时满足）

1. 连续运行不少于 2 小时，进程无异常退出（退出码 0 且非外部中断）；
2. 全部步骤通过（220 轮 × 10 步 = 2200 步，失败 0）；
3. 无漂移：`stability_trend.py` 半程中位漂移小于 ±15%
   （阈值依据：真机逐轮中位存在约 8% 的双峰自然振荡，判定阈值必须高于该幅度）。

## 二、启动

```bash
cd <项目根目录>
python -u examples/run_suite.py examples/cases/calculator.yaml \
    --repeat 220 --out tools/_out/stability_2h \
    --artifact-budget 60 --quiet > tools/_out/stability.log 2>&1
```

参数说明：

- `-u`：禁用输出缓冲，进程被终止时已产生的日志仍然保留；
- `--out`：每轮增量落盘 `suite_report_partial.json`，异常终止只损失
  正在执行的一轮，已完成轮次全部保留；
- `--artifact-budget 60`：产物轮转，长时间运行不会占满磁盘；
- 靶子使用 `calculator.yaml`：隔离变量，使失败可归因于框架本身；
  大应用的资源类长稳属另一场景（见第五节）。

## 三、运行中

- 不关闭终端、不终止 Python 进程——终端与进程本身就是被测对象的一部分；
- 不拔线、不手动操作设备（息屏无影响：引擎每轮自动重设息屏超时）；
- 随时查看进度：

  ```bash
  type tools\_out\stability_2h\suite_report_partial.json
  ```

  关注 `suite.cases`（已完成轮数）与 `elapsed_ms`（已运行时长）。

## 四、验收

```bash
python tools/stability_trend.py --report tools/_out/stability_2h/suite_report.json --strict
```

核对三项：日志尾部退出码为 0；报告 `failed=0` 且轮数为 220；
趋势工具结论为无漂移。三项全部通过后，将结果记入指标档案。

## 五、已知问题与处置

| 问题 | 现象 | 处置 |
|---|---|---|
| 日志全缓冲 | 后台执行时无法实时查看进度 | 使用 `-u`；查进度以 partial json 为准 |
| 外部终止 | 终端关闭导致进程退出，缓冲日志丢失 | 增量落盘已消除数据损失；执行期间不关闭终端 |
| 中途息屏 | 息屏锁屏后控件树为空 | 引擎每轮自动重设息屏超时 |
| 分离进程启动 | 每次 hdc 调用弹出终端窗口 | 禁止；长稳一律按本文的后台方式执行 |
| 双峰振荡误报 | 逐轮中位交替波动约 8% | 阈值 15% + 半程对比法，工具已按此校准 |

## 六、与应用长稳的关系

计算器 7+8 循环验证的是执行引擎通道本身的稳定性（隔离变量，靶子最简）。
真实应用长时间运行属另一场景：系统应用混合套件加资源遥测
（宿主内存、hdc 重启计数、设备内存曲线），执行方式见
`tools/b15_app_stability.py` 与 `tools/stability_telemetry.py`。
两类证据并列汇报，不互相替代。
