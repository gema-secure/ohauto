# ohauto 发展规划与改进建议

> 版本：v1.0（2026-10-09）
> 依据：全量代码评审（ohauto/ 包 22 文件约 1.9 万行、tools/ 50+ 脚本、
> 45 个测试文件 1384 项、README 与打包配置）
> 定位：本文件是项目从「单设备 UI 功能自动化能力层」走向
> 「通用于 OpenHarmony 生态的测试系统」的路线图。

---

## 一、现状总评

### 1.1 一句话结论

工程质量一流的**单设备 UI 功能自动化能力层**；离「通用鸿蒙测试系统」
还差三块拼图——**多设备规模化、宿主跨平台、测试维度补全**。
现有分层架构恰好为这三块留了扩展点，无需推翻重来。

### 1.2 优势（保持并放大）

| 优势 | 证据 |
|---|---|
| 全链闭环 | 采集→理解→定位→操作→断言→判定→归因→自愈→沉淀，每环有实现 |
| 契约驱动融合 | `Claim(kind,value,scope)` + 二元角色，加源不改融合器 |
| 定位器自愈 | 五级降级链、健康账本、快照回滚、视觉换通道三道闸 |
| 工程诚实度 | 降级显式声明、假绿系统性排查、弱证据不定案 |
| 测试资产 | 1384 项 / 91% 覆盖率 / 四道质量门禁，全不依赖真机 |
| 真机实证 | 大量隐蔽坑（file recv 假 0、cat 损坏 PNG、设备时钟域）已固化 |

### 1.3 短板（本规划要解决的）

**能力缺口（通用性）**
- C1 单设备串行，无设备池与并行编排
- C2 宿主 Windows 绑定深（venv 路径、winsdk OCR、hdc 搜索路径）
- C3 无运行时权限弹窗自动处理
- C4 无 CPU/内存/帧率/功耗采集（hidumper 能力未接入主链路）
- C5 断言原语弱（缺属性/数值/计数/图像 diff 断言）
- C6 危险控件黑名单与 prompt 仅中英文，国际化不足
- C7 视觉通道无人工真值标注集，准确率不可度量
- C8 技术路线单点依赖 uitest，无备用注入通路
- C9 hypium 导出是子集（swipe 等可实现未实现）
- C10 回归集缺管理侧（基线/趋势/调度）

**结构债务（可维护性）**
- S1 包反向依赖 tools/static_arkts，pip 安装即断
- S2 doctor.py 根目录 hack（py-modules 迁就文件位置）
- S3 50+ 散装脚本无统一 CLI
- S4 测试按日期命名，与被测模块脱钩；fixtures 与 datasets 重复
- S5 双 CI 配置（.github / .gitcode）漂移风险
- S6 版本号双源（pyproject 0.1.0 vs `__init__` 0.3.0）、license 未定
- S7 分层违例：locator(L3) 反向依赖 explorer(L4)
- S8 巨型文件（generator 2034 行等 5 个文件超 1200 行）
- S9 两个 OpenAICompatibleProvider 重复实现，别名是创可贴
- S10 Hdc 接口未形式化（Protocol 缺失、ShellResult.raw 动态挂属性）
- S11 隐藏实例级耦合（`_all_hints_cache`、模块级 `_OCR_VENV_ERR`）
- S12 平台常量硬编码（D 盘路径、%USERPROFILE% venv）
- S13 魔法数字靠注释对齐（VISION_IOU_MIN vs iou_threshold）
- S14 注释里写 changelog，编年史挤占代码
- S15 `except Exception` 无治理，长期退化风险

## 二、总体规划：四阶段路线图

```
Phase 0 快赢修缮        —— 1 周     发布级瑕疵清零
Phase 1 结构清偿        —— 2 周     包完整性 + 分层归位 + 重复归一
Phase 2 通用性补全      —— 1~2 月   跨平台 / 权限 / 性能 / 断言
Phase 3 平台化演进      —— 持续     多设备 / 回归管理 / 生态对接
```

原则：**每个 Phase 结束都是一个可发布状态**；结构债（Phase 0/1）
必须在能力扩张（Phase 2/3）之前清偿，否则新功能会继续向旧位置堆积。

---

### Phase 0：快赢修缮（1 周，各项 ≤ 半天）

| # | 事项 | 验收标准 |
|---|---|---|
| 0.1 | 版本号单源化：`__init__.py` 读 `importlib.metadata`，pyproject 为唯一源 | 两处版本一致，CI 加断言 |
| 0.2 | 选定开源协议（建议 Apache-2.0，与 OpenHarmony 生态主流一致） | LICENSE 文件落库 |
| 0.3 | `ShellResult.raw` 转正式字段，删除 `type: ignore` | static_check 零 error |
| 0.4 | IoU/置信度阈值常量提到 vision.py 共享，删「靠注释对齐」 | 单一出处 |
| 0.5 | fixtures 与 datasets 的重复 PNG 去重（引用清单或相对路径） | 仓库体积下降 |
| 0.6 | requirements.txt 收敛为 `pip install -e .[dev]` 指引 | 依赖单一声明 |
| 0.7 | `_VENV_PY` 支持 `OHAUTO_VENV_PY` 环境变量覆盖 | Linux 下可显式指定 |

### Phase 1：结构清偿（2 周）

**1A 包完整性**

- `tools/static_arkts/` 迁入 `ohauto/static_arkts/`，fusion 改包内导入，
  删除 sys.path 补丁【S1】
- `doctor.py` 迁入 `ohauto/doctor.py`，删 py-modules hack【S2】
- 双 CI 同步校验：quality-gate 加一步 diff 两份 workflow【S5】
- 验收：`pip install .` 后在**空目录**下
  `python -c "from ohauto import fusion"` 不因路径断链而降级。

**1B 分层归位**

- 新建 `ohauto/identity.py`：承载 `type_fingerprint / control_key /
  页面双签名 / 跨形态三级身份 key`，explorer、locator、crossform、
  fusion 统一从它导入【S7】
- 验收：`ohauto/locator.py` 不再 import explorer；分层依赖图可用
  `tools/static_check.py` 新规则自动校验（L3 不得 import L4）。

**1C 重复归一**

- 新建 `ohauto/llm_transport.py`：`post_chat() / extract_json_array() /
  env_triple()` 三个函数，vision 与 generator 的 Provider 各自薄封装【S9】
- 网络重试、超时、围栏解析的坑从此只需修一处。

**1D 接口形式化**

- 定义 `HdcLike(Protocol)`（runtime_checkable），Driver 注解放宽，
  FakeHdc 过 isinstance 检查；删除 refresh() 里的 getattr 兜底链【S10】
- `_all_hints_cache` 改显式传参；`_OCR_VENV_ERR` 收进对象【S11】

**1E 治理机制**

- static_check 新增两条规则：① 新增 `except Exception` 必须带
  `# noqa(原因)` 标记；② L3→L4 反向 import 报 error【S15】
- 存量豁免走一次性清单，只减不增。

---

### Phase 2：通用性补全（1~2 月）

按「先解锁 CI，再补维度」排序：

**2A 宿主跨平台【C2】**

- hdc 搜索路径补 Linux/macOS 常见位置；D 盘硬编码改为扫盘或仅信配置
- OCR 后端补 Linux 路线（rapidocr 已在 venv 回退链里，把它升为
  一等公民；tesseract 兜底）
- 在 Ubuntu CI 上跑通四道质量门禁，作为 Phase 2 的验收闸

**2B 权限弹窗处理【C3】**

- signals/explorer 增加「系统权限弹窗识别器」：按弹窗特征
  （bundleName 为系统权限 UI 进程 + 按钮文案「允许/仅本次/禁止」）识别
- 策略可配：auto-allow / auto-deny / 记录不动
- 探索器把它归入 URGENT 优先级档（复用现有四档机制）
- 验收：相机/通讯录类应用首次冷启动自动探索不被弹窗卡死

**2C 性能与资源采集【C4】**

- `signals.py` 增加 PerfChannel：hidumper 采样 CPU/内存，
  冷启动耗时已有，补 PSS 曲线、掉帧（可选）
- 把 `tools/stability_telemetry.py` 的能力收编进 `ohauto/perf.py`
- 断言原语同步扩展【C5】：`assert.checked / assert.enabled /
  assert.count / assert.memory_below` 等
- 验收：note_stability 类用例可在真机产出内存趋势曲线并入报告

**2D 视觉真值集【C7】**

- 建 50~100 张人工标注 bbox 的小型真值集（复用现有 13 应用截图资产）
- 新增 `tools/eval_vision_truth.py`：输出**准确率**而非双通道一致性
- 该指标成为换视觉模型的回归门禁

**2E 其余补全**

- hypium 导出补 swipe（运行时取 windowSize 换算方向+比例）【C9】
- 危险控件黑名单扩多语言（至少补俄/西/阿）【C6】
- uitest 不可用时的 sendevent 备用注入通路（可先做设计稿）【C8】

---

### Phase 3：平台化演进（持续）

**3A 多设备规模化【C1】**

```
ohauto/fleet/
    device_pool.py     # 设备注册/心跳/租借（复用 DeviceGuard 的看护逻辑）
    scheduler.py       # 用例 × 设备的分配（按 bundle 已装/形态分片）
    merge.py           # 多设备结果聚合进一份 SuiteResult
```

- 验收：3 台真机并行跑同一套用例，报告按设备维度聚合，
  总墙钟 ≈ 单台的 1/2.5

**3B 回归集管理【C10】**

- 用例基线版本化（用例 DSL 加 schema_version）
- 结果趋势落 SQLite（标准库），`python -m ohauto trend` 出曲线
- 失败用例自动关联 diagnose 归因，形成「缺陷-用例」闭环看板

**3C 统一 CLI 与子包拆分【S3/S8】**

- `python -m ohauto doctor|explore|crossform|quality-gate|...`
- generator/signals/runner 拆子包（`__init__` 重新导出，契约不变）
- 测试按 `test_<module>_<feature>` 归并，日期进 CHANGELOG【S4/S14】
- 建立 `docs/adr/`，代码注释只留不变式，修复史进 ADR

## 三、里程碑与度量

| 里程碑 | 时间 | 可度量的出口条件 |
|---|---|---|
| M0 快赢完成 | +1 周 | 版本/协议/常量/依赖全部单源；pip install 可用 |
| M1 结构清偿 | +3 周 | 分层依赖图零违例；Linux CI 全绿；重复 Provider 归一 |
| M2 通用性补全 | +2 月 | Ubuntu CI 常态化；权限弹窗用例通过；真值集准确率有数 |
| M3 规模化验证 | +4 月 | 3 设备并行回归跑通；趋势看板可查 |

**持续跟踪的北极星指标**（每门禁跑一次，写进 quality_gate 第 5 关）：

- 静态依赖违例数（目标 0，只减不增）
- `except Exception` 无标记数（目标 0，只减不增）
- 视觉通道准确率（真值集口径，换模型必测）
- 独立成功率（50 步连续执行，已有口径，保持 ≥95%）

## 四、风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 结构清偿期间引入回归 | 中 | 1384 项测试是安全网；拆分只动组织不动逻辑，契约导出保不变 |
| 多设备调度复杂度失控 | 中 | 先做 3 台固定设备的静态分片，不做动态调度 |
| LLM 依赖的不可控性 | 高 | 真值集 + 静态校验闸双保险；离线路径（MockProvider）保持可用 |
| 生态 API 演进（uitest 变更） | 中 | doctor 检测项持续扩充；HdcLike Protocol 让替换通路成本最低 |
| 人力不足导致 Phase 堆积 | 高 | 每 Phase 独立可发布；快赢清单任何一项都能单独捡起做 |

## 五、决策记录（本规划的取舍）

1. **先结构后能力**：Phase 1 全部是内部重构、不新增用户可见功能。
   理由：现有分层契约（`__init__` 稳定导出 + 全限定导入的测试）是
   拆分红利，越晚兑现利息越高。
2. **不推翻架构**：三块拼图（多设备/跨平台/维度）全部落在既有
   扩展点上（DeviceGuard → device_pool、Hdc 封装层 → HdcLike、
   signals → PerfChannel）。
3. **真值集优先于换模型**：没有准确率口径之前，任何视觉模型升级
   都无法证明「更好」。
4. **多语言黑名单放 Phase 2 末尾**：先保证中文生态（当前主力场景）
   的完整，国际化随生态需求加权。
