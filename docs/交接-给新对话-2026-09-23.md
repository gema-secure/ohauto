## 六、已知的坑（**踩过的，别重复踩**）

### 6.1 环境

| 坑 | 现象 | 处理 |
|---|---|---|
| shell 是 cmd.exe | bash 语法全挂 | 用 `&&` / `%VAR%` / Windows 路径 |
| Python 路径 | `python` 可能找不到 | 用绝对路径（§1.4） |
| Git Bash + hdc 文件传输 | `/data/local/tmp/x` 被改写成 `C:/Users/../data/...` | **一律用 Python `subprocess` 直连** |
| MSYS 路径改写（写文件时） | heredoc 里的反斜杠被全改成斜杠 | **用 Write/Edit 工具写，不要走 heredoc/echo** |

### 6.2 真机（四个坑，全影响可复现性）

1. 🔴 **`aa start` 复用实例、不回到入口页** → 必须 `aa force-stop` → `keyEvent Home` → `aa start` 三步
2. 🔴 **`pagePath` 在 `attributes` 里**（`node.attributes['pagePath'] = 'pages/settingList'`），
   不是内联文本 —— 按正则搜 `pagePath=xxx` **永远读到空串**
3. 🟠 **可点控件自身 `id/text/descr` 全空**（设置首页 11/11 = 100%），文案在 `text_deep`
4. 🟠 **hdc 通道间歇失败**（`need connect-key?` / `channel is being established`）
   → 等 1–2 秒重试；`hdc kill` + `start` 可根治

### 6.3 设备状态类

- **设备 30 秒息屏 → 锁屏不进无障碍树 → `uitest dumpLayout` 返回 377 字节空树**，
  且**输出里一个错误都没有**（探索后半程在盲跑）
  → 三步修：`power-shell wakeup` → `power-shell timeout -o 1800000` → `uitest uiInput swipe 360 1152 360 448 600`
  → **生产类已有** `runner.py:198 DeviceGuard.ensure_awake()`，**复用它，别抄逻辑**
- **设备 RTC 可能停在 2017（偏差 9.1 年）** → 做信号/崩溃相关前先
  `python tools/sync_device_time.py --target <序列号>`
  ⚠️ 跑**全量测试前先拔真机**，否则 `test_sync_device_time` 会真的去改设备时间

### 6.4 编码/度量类（**这类坑最贵**）

- **`Hdc.shell()` 返回 `ShellResult` 对象，不是 str** —— 拿它做 `in` 判断报 `TypeError`
- **`StepResult.trees` 存的是文件路径**，而 `_parse_trees` 只做 `parse_layout(t)`
  → 直接赋值 = 从「恒空」变「恒 None」，**更坏** → 要读文件内容（见 `diagnose._load_step_trees`）
- **`non_cascade_failure_rate` 不是成功率** ——
  既有测试里真实存在反例：50 步挂 5 步 → 该值 `0.98`（漂亮）但 `failed=5`、`ok=False`，
  **旧口径 `kpi_ok(0.95)` 判「达标」**。现在 `kpi_ok()` 是**两道闸**（`health_ok` + `non_cascade_failure_rate`）
- **白屏判据别照抄 B 的建议到原位置** —— 截图（步骤 3）跑在控件树（步骤 4）**之前**，
  那一刻 `layout_nodes` 必然是 `None`。C 改成「3 出原始判据 → **6.5 用节点数复核**」两段
- **文案采样必须排除状态栏**（`top < 72`），否则每页前 4 条永远是「没有 SIM 卡 / × / 11% / 08:40」
- **「检测到问题」≠「处理了问题」** —— 只打印警告的分支，在无人看输出的批处理里等于不存在
