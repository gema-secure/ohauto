## 附录 B：hdc BOM 事后核查（3②）

**结论：查不清 —— 历史数据未留 hdc 通路记录，已按裁定加对外注记。**

核查过程与证据：

1. 缺陷机理（9f0bb37 修复，hdc.py:255-260）：hdc.config.json 若带 BOM，
   `json.load` 解析失败 → 配置被**静默跳过** → `_locate()` 落到 PATH /
   常见安装位置 → 可能用上与配置目标**不同的 hdc 二进制**。修复 = 读配置改
   `utf-8-sig` + 带测试。
2. 历史留痕检查：datasets/（gallery_13app、b15_note_tree.json 等）与报告
   产物中**均无 hdc 路径或版本字段**；`tools/configure_hdc.py` 会跑 `hdc -v`
   验证可用性，但结果不落盘。→ 受影响窗口内无法回溯「当时的树是谁采的」。
3. 已做的对外注记：README 指标表下方新增「数据留痕说明」（B6 延迟、视觉
   一致性 95%/97.8%、真机执行 23/24 等数字适用）。
4. **前向修复（待派任务）**：后续采集批次在数据元数据中记录
   `hdc_path` + `hdc -v` 输出（建议挂在 explorer/driver 的报告元数据里，
   一次性成本 ≈ 半小时）；owner/时间待主责 AI 指派。
