## 一、C 出的接线方案（你实现，细节可调，方向先对齐）

### 1. 入口：Explorer 两个可选参数

```python
Explorer(driver, ..., vision_provider=None, ocr_fn=None)
```

- `vision_provider`：`ohauto.vision` 的 Provider（**复用，不重写**——它的
  结果缓存、分层降本、置信度都已就绪）；接口用 `locate(image, instruction, w, h)`
  → `VisualTarget(label, rect, confidence)` 列表；
- `ocr_fn`：传 `fusion.source_ocr` 包一层（或直接接 `tools/ocr_worker.py`）；
- **两者都为 None 时行为与现在完全一致**（零回归是验收第一条）。

### 2. 触发条件：「半盲页」判定（别每页都调，钱和延迟都花在刀刃上）

新页面指纹计算完成、可交互候选收集完之后：

```python
if len(候选) < BLIND_PAGE_THRESHOLD and vision_provider:   # 阈值建议 3
    → 该页判定为「半盲页」→ 截图（复用既有 artifact 通道）→ vision.locate(...)
    → OCR 同理（文本候选）
```

- 每页**至多一次** vision 调用（provider 自带缓存按图去重——**B14 的缓存
  命中率就从这里出数**）；
- 截图复用 Driver 既有 screenshot 通道，不新增落盘路径。

### 3. vision 候选的处理（三条硬约束）

1. **安全围栏必须覆盖**：vision 返回的 label 当文本过 `SafetyPolicy.deny_patterns`
   ——「支付」「删除」不会因为视觉看见了就被点；
2. 候选入队列时标记 `kind='vision'`（note 里记 label + bbox + confidence），
   点击走 `driver.tap_xy(bbox 中心)` —— 运行时探索用坐标是合法的
   （底层全是坐标），但：
3. **沉淀契约（红线）**：vision 步骤进 `generate_case`/`trace_to_steps` 时
   一律 `unresolved` 占位（控件树里没有它的 node_spec）——**产物里绝不出现
   tap_xy**（这条已有钉子 `tests/test_attack_surface.py` 之外还有 c_trace_case
   的零坐标钉，别破）。

### 4. 度量出口（B14 的 KPI 就靠它）

```python
ex.vision_stats = {'calls': 0, 'cache_hits': 0, 'suggested': 0, 'tapped_ok': 0}
```

- `cache_hits / calls ≥ 60%` 就是 B14 的 KPI 数字（同一页二次访问时
  provider 缓存命中）；
- stats 随 `save_graph()` 的 payload 一起落盘。

## 二、验收

### 离线钉子（不依赖真机/key，全部要过）

1. 盲页触发：FakeHdc 页面 0 个树候选 + stub provider 返回 2 个目标 →
   两个候选入队、`vision_stats.calls == 1`；
2. 非盲页不触发：正常页面（候选 ≥3）→ `calls == 0`；
3. 安全围栏：stub 返回 label「支付」→ 候选被拦，进 `skipped_controls`；
4. 默认关闭：不传 provider → 与现状逐字节一致（跑既有探索测试即证）；
5. 沉淀红线：含 vision 步骤的探索 → `generate_case` 产物 grep 不到 `tap_xy`，
   vision 步为 unresolved 占位；
6. 缓存计数：同页二次探索 → `cache_hits == 1`。
