## 三、合入决定（三处取舍，都有依据）

### 3.1 `layout.py` —— **不合入，保留仓库版**

A 在修改说明 §5 主动预判了这一处，并授权「合并时以仓库版为准」。我复核后**同意**，且有两条技术依据：

1. **仓库版的 `label` 已纳入 `text_deep`**（`text→descr→hint→text_deep→id→type`），
   而 A 包里的 `label` 是 `text→descr→hint→id→type` —— **丢了一层兜底**。
   这层是 09-22 真机实测后加的：真机形态是 `Flex(id='item_reset', text='')` +
   子节点 `Text('恢复出厂设置')`，若 `id` 优先，日志里这个危险按钮就叫
   `item_reset`，而安全策略按文案匹配「恢复出厂」照样找不到它。
   整文件覆盖会把这个修复**静默回退**。

2. **`text_deep` 本身：仓库版 ⊇ A 版**。两者都是「自身 text 非空直接返回，
   否则先序借子树文案去重」，唯一差异是**自身 text 为纯空白**时：
   仓库版 `(self.text or '').strip()` 视为空 → 继续借子树；
   A 版 `if self.text` → 返回空白串。**仓库版更稳健**。

> 事实核查：`layout.py` 的 diff 是 **25 增 / 47 删**，是这一批里唯一「删多于增」
> 的文件 —— 正是上面两处被回退的表现。**只看文件名相同就覆盖，会丢掉已修好的东西。**

A 的 `TestTreesumBorrowChildText` 4 条在仓库版 `layout.py` 上**全绿**，
说明两版 `text_deep` 在测试覆盖面上行为等价，保留仓库版不削弱 A5。

### 3.2 `vision.py` 的 `available()` —— 集成层对齐（**红灯 R1**）

A 把 `available()` 从「三件套各自在任一前缀里取到值」改成
「**任一一组**三个变量配齐」，但 `from_env()` 仍是**逐变量**回退取值 ——
两者在**跨组混搭**配置下分叉。

**实测证据**（`_out/probe_env_consistency.py`，5 个场景）：

| 场景 | available() | from_env() | 一致 |
|---|---|---|---|
| A) 一组配齐 `OHAUTO_LLM_*` | True | True | OK |
| B) 一组配齐 `OHAUTO_VISION_*` | True | True | OK |
| **C) 混搭：`VISION_BASE_URL` + `LLM_API_KEY` + `LLM_MODEL`** | **False** | **True** | **矛盾** |
| **D) 混搭：`VISION_BASE_URL`+`VISION_API_KEY` + `OH_LLM_MODEL`** | **False** | **True** | **矛盾** |
| E) 全空 | False | False | OK |

后果正是 C 在 09-22 修过的那个 bug 回归：**上层按 `available()` 决定是否启用
视觉通道 → 用户明明配好了 key，视觉通道被静默跳过。**

**为什么不能反过来把 `from_env()` 改成按组**：A 自己的
`test_vision_group_has_priority` 就是混搭场景（`VISION_MODEL` 覆盖 `LLM` 组的 model），
按组实现会让那条测试失败；而且「DeepSeek 生成用例 + Qwen-VL 看图」分开配
正是逐变量回退存在的理由。**所以只能让 `available()` 与 `from_env()` 对齐。**

**集成层已改**（`vision.py` 的 `available()` 恢复逐变量语义，docstring 写明理由与
实测出处），并**固化成回归钉子** `tests/test_c_env_consistency.py`（3 条，全绿）。
改后复跑探针：**矛盾场景数 0**。

> 性质说明：这与上一轮 C 在集成层修 B 的 `diagnose.py` 同性质 ——
> **集成仓以「能跑通 + 自洽」为准，改法写进回执，请你收口或提出异议。**
> 若你认为该保留按组语义，请同时改 `from_env()` 与那条测试，让三者自洽。

### 3.3 `test_a_vision.py` 的 2 条用例 —— C 按你的说明改

你的说明里写了「旧测试仅 `test_a_vision.py` 里 2 条按新 L1 口径改了用例数据
（文件内注释写明原因）」，但**该文件没有随包交付**（包里只有
`test_a_defects_20260923.py`）。结果是合入你的新 `vision.py` 后，

```
FAIL: test_l2_called_when_l1_ambiguous    → cp.calls: 0 != 1
FAIL: test_crop_fn_hook_used_in_l2        → cropped['used'] is False
```

两条用例造的是「候选文案与指令**相等**」（都是 `'搜索'`），而新 L1 口径下
「相等」会直接免调模型返回、不再升级 L2 —— 这正是免调模型率从 10% 涨到 70%
的原因，**用例失败是口径变更的必然结果，不是代码错**。

我按你说明的口径改成「包含但不相等」（`'搜索设置'` ⊃ `'搜索'`），
文件内注明原因，两条随即转绿。`tests/` 在分工卡里归 C，所以由我落地。
