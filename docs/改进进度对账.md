## 三、已完成：1D 接口形式化【S10+S11】

- 新增 `HdcLike(Protocol)`（`hdc.py`，`runtime_checkable`）：**窄契约**，只声明 `Driver` 实际消费的 15 个方法与 `tmp_dir` 属性（接口隔离，不照抄 `Hdc` 整个公共面）。

- 注：`runtime_checkable` 的两个限制 —— 3.12+ 的 `isinstance` 会连数据成员一起查，而 `issubclass` 遇数据成员直接报错，检查一律走 `isinstance`。

## 十二、视觉通道（GLM-5.3-flash）实测 —— 2D 挂账依据

> 状态：**只读评测，未改任何代码**。用于回答「2D 视觉真值集该不该做」。
> 凭据纪律：智谱 key 只放进会话环境变量，**未写入任何文件、未提交**。

**环境**：`tools/eval_vision_offline.py --provider openai`；
base_url `https://open.bigmodel.cn/api/paas/v4`；model `glm-5.3-flash`。

**结果**（n=46，数据集 `datasets/gallery_13app`）：

| 指标 | 值 |
|---|---|
| IoU@0.5 / IoU@0.3 / 中心命中 | 97.8% / 97.8% / 97.8% |
| 控件树 L1 免调模型 | 67.4%（31 条） |
| 模型实际调用 | 15 条，命中 14 条（93.3%） |
| 延迟 min / p50 / max | 2019ms / 3208ms / 19088ms |

**唯一失败**：`app_settings \| 蓝牙` —— 模型返回 `[42,72,678,122]`，
真值 `[36,156,684,213]`，**指错了行（偏上约 84px）**。属「调阈值救不了」的类型。

**诚实归因（一次自造的坑）**：首次运行全 400，根因是我给工装加了
`--no-thinking` —— GLM 回 `{"error":{"code":"1210","message":"该模型始终思考，
不支持关闭思考；请使用 low、high 或 max。"}}`。去掉该键即正常。
**顺带暴露一个可修的潜在 bug**：生产类 `OpenAICompatibleProvider` 的
`disable_thinking=True` 对「始终思考」类模型会 100% 400，用户会误以为模型不行
（是否修由主责 AI 裁决，本次未动）。

**口径声明（必须随数字一起读）**：上述 97.8% 是「视觉 vs 控件树」**一致性**，
**不是视觉绝对准确率** —— 绝对准确率只能在控件树盲区上测。本次盲区 9 条
（`app_note` 2 / `camera` 2 / `certmanager` 1 / `contacts` 3 / `launcher` 1，
均为「仅 id 0 / 无标识」）。

**结论**：2D【C7】**挂账**（2026-10-09 用户裁定先推 2E）。2D 的价值锚点不是
现有指标，而是「盲区上的绝对准确率」与「调阈值救不了的错误类型」。
