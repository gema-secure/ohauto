## 一、（P0）`text_matches` 没有资源上限 → ReDoS —— 红队洞 ①

**现状**（实测，不是推断）：`matcher.py:72` 把调用方给的正则直接编译使用：

```python
rx = re.compile(pattern, flags)
```

`ON.text_matches(r'(a+)+$')` 对 **28 个字符**回溯 **17.63s**（当场计时）。

**复现**：

```bash
python -c "import time,sys; sys.path.insert(0,'.'); from ohauto.matcher import ON; from ohauto.layout import LayoutNode,Rect; n=LayoutNode(type='Text',text='a'*28+'b',rect=Rect(0,0,10,10)); t=time.perf_counter(); ON.text_matches(r'(a+)+$').match(n); print(round(time.perf_counter()-t,2),'s')"
```

**为什么必须修**：匹配发生在 runner 的每一步里，**步上限打断不了一次阻塞的匹配**——一条敌意或误写的正则就能把长稳挂死。

**修法**（实现你定，给 C 过目）：给正则加资源闸，两条路都行——

- 编译时拒绝明显灾难性的模式（嵌套量词：`(...)+` / `(...)*` 里再含量词）；
- 或匹配前对输入长度设上限，超限直接不匹配并记一条降级说明。

无论选哪条，**降级必须是"响亮地说没做匹配"**，不能静默返回 `False`（红线 5：只打印警告不处置等于不存在）。

**钉子**：把 `tests/test_attack_surface.py:126` 的 `@unittest.skip(...)` **摘掉**（测试体已经写好了），
再加一条"超长输入不被匹配、也不阻塞"的钉子。**摘标记，别删测试。**

**验收**：

```bash
python -m unittest discover -s tests -t tests -p "test_attack_surface.py"   # 期望：不再有 skipped
python tools/quality_gate.py
```

`parse_layout` 直接 `json.loads` → 裸抛 `JSONDecodeError`。实测：

```
>>> parse_layout('[Fail]Not match target founded, check config or confirm the key')

```

后果：几个工具在**设备不在场时崩栈**，而不是如实说"设备没插"——违红线 2，而且看起来像代码有 bug。
C 侧已经给一部分工具接了 preflight，**深层在你这里**。

**修法方向**：

- (a) 建树改显式深度上限（或改迭代式），超限返回已解析的部分 + 一条"深度截断"说明；
- (b) 输入不是 JSON 结构时抛项目自己的异常（或返回 `None` + 原因），并把 `[Fail]` 开头的文本识别成"设备侧失败"这类明确原因。

**钉子**：摘掉 `tests/test_attack_surface.py:104` 的 `expectedFailure`；
(b) 新增一条——喂 `[Fail]...` 文本，断言拿到的不是 `JSONDecodeError`，而是项目自己的错误类型或 `None` + 原因。
