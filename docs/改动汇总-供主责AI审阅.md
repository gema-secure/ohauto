## 一、项目初衷（审查基准，引自 README 与规划文档）

1. **定位**：OpenHarmony 应用 UI 自动化能力层 —— hdc 通路、**设备侧零部署**、
   不为被测应用打包测试 HAP。
2. **主链**：采集 → 理解 → 定位 → 操作 → 断言 → 判定 → 沉淀；失败时自动归因 →
   自动修复 → 重跑。
3. **多模态**：控件树 + 视觉双通道，证据按 `Claim(kind,value,scope)` 契约融合裁决。
4. **工程诚实度**：降级显式声明、假绿系统性排查、弱证据不定案。
5. **演进方向**（规划文档 v1.0）：从「单设备 UI 功能自动化能力层」走向
   「通用于 OpenHarmony 生态的测试系统」；**结构债必须在能力扩张之前清偿**。

## 四、三处关键取舍（偏离审查的核心素材）

### 1. 2B 实现与规划原文的写法偏离

规划原文：探索器把权限弹窗**归入 URGENT 优先级档**（复用现有四档机制）。
实际实现：**在候选生成之前先作答**，弹窗根本不进候选列表。
理由：弹窗不是「要探索的控件」，进候选再排队多绕一轮且档位语义不符；
先作答比排队更彻底。风险：若有场景需要「记录弹窗但暂不处理」，
现在的三档策略里「记录不动」档仍可覆盖。**请主责 AI 裁定是否接受此偏离。**

### 2. 2A 宿主跨平台【C2】按决策放弃（2026-10-09）

理由：系统面向 OpenHarmony 单一生态，宿主锁定 Windows。
代价（已明示接受）：CI 仅有 Windows 一条；Linux/macOS 下 pip 安装不保证可用。
连带影响：M1 里程碑出口条件里的「Linux CI 全绿」随之取消，M1 以
「分层零违例 + 重复 Provider 归一」为准（均已达成）。
**请主责 AI 确认：「通用性」缺口清单里去掉 C2 后，剩余 C1/C4~C10 是否仍支撑
「通用于 OpenHarmony 生态」的定位。**

### 3. 性能第一批：做了一半、撤了一半

- **保留**：`wait_idle` 判稳基线复用动作前已 dump 的树（原本动作后连取两次树
  才算稳）。页面未变的常见路径每交互省 1 次全量 dump，离线端到端
  10.1s → 4.1s。语义变化：判稳证据从「动作后连看两眼一致」变为
  「动作前后一致」—— 对未变页面证据不弱；对晚到的页面跳转，
  由后续页面签名处的**无条件 refresh** 兜底捕获（见下）。
- **撤销**：曾把页面签名/候选生成的默认取树改为复用缓存树，
  被 test_explorer_b1 两条测试证伪 —— `_tree_dirty` 只看得见宿主动作，
  设备**带外自变**（晚到跳转/通知/异步加载）只有无条件重取才能兜住。
  撤销后不变式已写进 `_page_signatures` 文档，防止后人再犯。
- **请主责 AI 裁定**：判稳语义的上述变化是否触碰「弱证据不定案」底线
  （执行侧论证：带外变更兜底仍在，且导航判定全部走无条件 refresh 路径）。
