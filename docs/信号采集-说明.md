## 一、采集了哪些信号

一次 `collect_signals(hdc, bundle, ...)` 采下面六类，全部落盘成 JSON（`Signals.to_dict()`），
**只输出客观证据 + 异常识别 + 置信度，不做归因判断**：

| 信号 | 来源 | 用途 |
|---|---|---|
| 崩溃日志 | `/data/log/faultlogger/`（**只读这个正式归档目录，不读 `temp/`**） | 主证据 |
| 进程存活 | `pidof <bundle>` | 崩溃辅证 |
| 截图 | `uitest screenCap` + 零依赖 PNG 解码 | 白屏判据 |
| 控件树 | `uitest dumpLayout` | 无窗口 / 无响应判据 |
| hilog | `hdc.hilog()`（**必须带 `-x`**） | 关键词辅证 |
| 设备时钟 | `date +%s` | 采集窗口锚点 |

产物目录（`out_dir`）：崩溃日志原文 `<out>/*.log`、截图 `<out>/screen.png`、控件树 `<out>/layout.json`、结构化结果 `<out>/signals.json`。

**`collect_signals()` 除参数错误外不抛异常**，任何一步失败都记 `warnings` 并降级继续。

## 二、每种异常的判据与置信度

置信度是「这条独立证据有多可信」，不是「异常有多严重」。同类多条证据按
`1 - Π(1 - cᵢ)` 合成（上限 0.99），由 B4 决定怎么用。

### 崩溃 CRASH

| 判据 | 来源 | 置信度 |
|---|---|---|
| 窗口内 + bundle 匹配的崩溃日志，且 `Module name` / `Reason` / `Timestamp` 解析成功 | `faultlog` | **1.0** |
| 进程已不在 `pidof` 输出中，**且**有崩溃日志 | `hdc` | 0.9 |
| 进程已不在 `pidof` 输出中，但**没有**崩溃日志（也可能是被 force-stop / 系统回收） | `hdc` | 0.35 |

### 白屏 WHITE_SCREEN

两条思路，**B 结果具有权威性**（能给出「整屏就是一个颜色」这种硬证据），A 只在解码不可用时兜底：

| 判据 | 来源 | 置信度 |
|---|---|---|
| **B** 像素直方图：单一颜色占比 ≥ 95% | `screenshot` | = 该占比（≤ 0.99） |
| **B** 颜色分散 | `screenshot` | 0.0（**明确否掉** A 的误报） |
| **A** 体积启发式：≤ 0.006 字节/像素（按字节/像素归一化，与分辨率无关） | `screenshot` | 0.8 |
| **A** 0.006–0.06 字节/像素 | `screenshot` | 线性 0–0.8 |

### 无响应 NO_RESPONSE

任务卡明确要求**不单信号硬判**，所以只叠加证据：

| 判据 | 来源 | 置信度 |
|---|---|---|
| `freeze/` 出现窗口内新文件（**该目录命名格式未实测验证**） | `faultlog` | 0.9 |
| hilog 出现 `freeze` / `ANR` / `THREAD_BLOCK` 等关键字 | `hilog` | 0.45 |
| 控件树多轮探测全都是同一棵树（需显式 `probe_rounds > 1`，默认关闭） | `layout` | 0.3 |

> ⚠️ **最后一条是本模块最弱的判据，B4 消费时务必看上下文**：两次探测之间若
> **没有注入过任何操作**，控件树本来就该一模一样（静止的页面不会自己变），
> 此时这条证据**恒为真、毫无信息量**。它只在「刚刚注入过一次本应改变界面的操作」
> 的上下文里才成立。因此：置信度压到 0.3、默认 `probe_rounds=1` 不产生、
> evidence 文本自带免责说明。**别把它单独当「应用无响应」的结论用。**

### 无窗口 NO_WINDOW

复用 `runner.py::DeviceGuard.has_window()`：

| 判据 | 来源 | 置信度 |
|---|---|---|
| `has_window()` 判无窗口 **且** 控件树节点数 ≤ 1（两路独立印证） | `layout` | 0.95 |
| 仅 `has_window()` 判无窗口，取不到控件树 | `layout` | 0.4 |
| 仅控件树 ≤ 1 个零尺寸节点，`has_window()` 探测失败 | `layout` | 0.6 |

## 三、采集窗口（最容易出错的地方）

`faultlogger/` 会累积历史文件，而崩溃发生在调用 `collect_signals()` **之前**，
所以窗口是「`since`（或 `now - lookback_s`，默认 600 秒）→ 现在」。

**窗口锚在设备时钟域**，不是本机时钟域 —— 因为文件名里的 `YYYYMMDDHHMMSS` 和
`ls -l` 的 mtime 都是设备时钟域的。真机上设备 RTC 实测卡在 **2017-08-05**，
直接拿本机时间比会把所有崩溃判成「窗口外」。

窗口只有下界不够。真机上 RTC 从 2026 回跳到 2017 后，回跳**之前**写的旧日志
带着「未来」时间戳留在目录里，`when >= win_start` 会把它们全部误采纳。
所以还有一条上界：**时间戳晚于当前设备时间 + 120 秒容差 → 判为跨时钟回跳的旧日志，剔除**。
（一个日志文件不可能在设备当前时间之后才被写出来。）

设备时钟与本机相差超过 1 天时会在 `warnings` 里点明，避免读者以为产物里的时间戳写错了。

## 四、真机验收结果（2026-09-17，润和 DAYU200 / OpenHarmony 5.0.3.135 / API 15）

按任务卡第三章（四）的步骤实打实注入了一次崩溃（`aa force-stop` → `aa start` → `kill -11 <pid>`），
**真杀进程，不是模拟**：

```
faultlogger/ 注入后同时存在两份同名应用崩溃日志：
  cppcrash-com.ohos.note-20010019-20170805172040   ← 刚注入的（设备时钟域）
  cppcrash-com.ohos.note-20010019-20260916151446   ← 9 小时前的，RTC 回跳前写的

collect_signals(h, 'com.ohos.note') →
  faults_in_window : ['cppcrash-...-20170805172040']       ← 只认这一份
  module_name      : com.ohos.note                          ✓
  reason           : Signal:SIGSEGV(SI_USER)@0x00000bda from:3034:0   ✓
  signal           : SIGSEGV                                ✓
  timestamp        : 2017-08-05 17:20:40.000                ✓
  pid / uid        : 2965 / 20010019                        ✓
  raw_path         : <out>/cppcrash-...log（390452 字节，已落盘）✓
  CRASH 合成置信度 : 0.99（faultlog 1.0 + hdc 0.9 两条独立证据）
  warnings         : 时钟偏差 -3330 天 + 旧日志剔除说明
```

同一目录里旧文件与新文件**并存**，窗口把两者正确分开 —— 这比「目录里只有一份文件」是强得多的验证。

无真机时同样的链路可以用 `python examples/collect_signals.py --bundle com.ohos.note --sim` 走通。

## 四·补、`FakeHdc` 截图默认值（2026-09-16 独立验收修复）

**结论：`FakeHdc()` 的 `screen_style` 默认值已从 `'solid'` 改为 `'content'`。**
如果你在 2026-09-16 之前写过依赖默认值的测试，需要看一眼。

**原缺陷**：`screen_style='solid'` 会渲染出一张**纯色** PNG；白屏判据（单一颜色
占比 ≥ 95%）对纯色图必然成立，于是**干净场景下 `FakeHdc()` 恒定报
`WHITE_SCREEN` 置信度 0.99**。B4 若直接消费 `sig.has('WHITE_SCREEN')`，就会把
一次完全正常的执行判成「应用白屏缺陷」。**测试全绿反而是最危险的状态。**

**根因不是判据写错**（`signals.py` 的白屏判据对真机截图是正确的），而是
**模拟器的默认值与真机语义不符**：真机截一张正常页面，像素是分散的。
默认值必须模拟「真机常态」，而不是模拟「某种故障」。

**修复后的行为**（已实测四场景）：

| 调用 | `anomalies` |
|---|---|
| `FakeHdc()` ← 默认 | **无异常**（正确；改前是 WHITE_SCREEN 0.99） |
| `FakeHdc(screen_style='solid')` | `WHITE_SCREEN` 0.99（白屏判据仍可用） |
| `FakeHdc(dead_bundles=['com.ohos.note'])` | `CRASH` |
| `FakeHdc(frozen=True)` | 单轮无异常；`probe_rounds≥2` 时出现 `NO_RESPONSE` 0.3 |

**新增 4 条回归护栏**（`tests/test_signals.py`，101 → 104 项）：
`test_default_sim_does_not_fabricate_white_screen`（钉死不误报）、
`test_default_screen_style_is_content`（钉死默认值）、
`test_screen_style_does_not_collide_on_temp_file`（防两种 style 共用临时文件互相覆盖）、
以及原白屏测试改为**显式** `screen_style='solid'`（不再隐式依赖默认值）。

**要测白屏判据，必须显式传 `screen_style='solid'`。**

## 五、未验证项（不要当成已知事实）

1. **`freeze/`（ANR）的文件名格式没有实测验证过** —— 真机上该目录实测为空。所以
   NO_RESPONSE 只叠加证据、给中等置信度，不做硬判。
2. **js 崩溃（`jscrash`）的字段**未实测，解析器按宽松模式处理（未知字段进 `extra`，不丢）。
3. **非 root 设备能否读 `faultlogger/`** 未验证 —— 真机上 `hdc shell` 是 root。
   读不到时会降级为空列表 + warning，不抛异常。
4. **多用户 / 多 display** 未验证，窗口按单个主体处理。
5. **`pidof` 为空不等于崩溃**（可能是 force-stop / 系统回收），因此单独出现只给 0.35。
6. **白屏判据是启发式**：内容稀少的复杂页面体积也可能偏小。像素直方图（思路 B）能
   否掉这类误报，但解码失败时会退回体积启发式，此时准确度下降。

## 七、给 B4 的接口

```python
from ohauto import collect_signals          # Signals / CrashRecord / Anomaly 也导出了

sig = collect_signals(d.hdc, 'com.example.app', out_dir='./_out/signals')
sig.anomaly_score('CRASH')                  # 合成置信度（同类证据概率组合，上限 0.99）
sig.of_kind('CRASH')                        # 该类全部独立证据
sig.has('WHITE_SCREEN')                     # 是否识别到
sig.crashes                                 # [CrashRecord]，字段见下
sig.to_json('signals.json')                 # 落盘，直接喂 B4
```

`CrashRecord` 字段：`module_name` / `pid` / `uid` / `timestamp` / `timestamp_epoch` /
`reason` / `signal` / `foreground` / `process_life_time` / `stack_head` / `raw_path` /
`source_file` / `kind` / `extra`（未识别字段一律进这里，**不丢信息**）。

**三处与任务卡「建议结构」的差异，B4 消费时请注意**（都是刻意为之，卡片里也说建议非强制）：

1. **`foreground` 是 `Optional[bool]`，三态而非两态**。取值 `True` / `False` / `None`，
   `None` = 日志里**没有** `Foreground` 字段或解析不出。任务卡建议的是 `bool`，
   但把「不知道」压成 `False` 等于**伪造证据** —— B4 会把「后台崩溃」和「不知道」
   当成同一回事。判「是否前台」请用 `rec.in_foreground`（`foreground is not False`），
   它把 `None` 当「不排除前台」处理。
2. **`module_name` 可能是空串**，表示文件名和正文都没给出模块名，**不做推测**。
   这种记录仍然会被采纳（丢证据比多一条可疑证据更糟），但会在 `warnings` 里点明。
   B4 不要把空串当「不是这个应用」。
3. **`reason` 里的信号名另外解析了一份到 `signal`**（如 `'SIGSEGV'`、`'SIGABRT'`），
   免得 B4 再去正则拆 `Reason` 字符串。`reason` 原文照旧保留。

`Signals.to_dict()` 定稿字段（契约）：
`bundle` / `captured_at` / `device_time` / `window_start` / `hilog_tail` / `crashes` /
`anomalies` / `screenshots` / `layout_path` / `warnings` / `process_alive` /
`layout_nodes` / `faults_in_window`。

**注意**：`captured_at` 是本机时钟域，`device_time` 与所有崩溃时间戳是设备时钟域，
两者在 RTC 不准的设备上**不可直接比较**。判据与窗口一律用设备时钟域。
