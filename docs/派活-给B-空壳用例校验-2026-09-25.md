## 一句话结论

校验器逐条检查每一步的合法性，但**没有一条「用例整体必须做事」的总闸** ——
只含 `start` / `waitIdle` / `screenshot` 的空壳用例每步都合法、顺利放行。
L3 真机实测把后果钉死了：**空壳用例 2/2 全过，真引用控件的用例 0/3 整全过**。

## 根因（行号级证据）

- 759-773：硬编码坐标红线 —— 逐步 ✓

## 修法（建议，实现细节你定）

在 `validate_case` 里加一条**用例级**检查（建议放在 `if not case.steps` 之后）：

```python
    # ---- 用例级总闸：「至少做一件事」
    #      只含 start/等待/截图的空壳用例每一步都合法，但什么都没验证 ——
    #      「可执行」≠「做了事」（2026-09-25 L3 实测：空壳 2/2 全过、
    #      真引用控件 0/3，见 docs/指标汇总-2026-09-24.md §十一之四点五）。
    _NO_REF_ACTIONS = {'start', 'launch', 'waitIdle', 'waitGone',
                       'screenshot', 'sleep'}
    if all(action in _NO_REF_ACTIONS
           for _, action, _ in _iter_steps(case.steps)):
        issues.append(ValidationIssue(
            RejectReason.EMPTY,       # 或新增 EMPTY_CASE 分类，你定
            '用例没有引用任何控件或断言（只有启动/等待/截图）—— '
            '这样的用例什么都没验证，不能当有效测试'))
```

要点：

1. **`waitGone` 归入「不引用控件」是否合理请把关**——它是具名等待，
   可能带 spec？按你 `_WAIT_ACTIONS` 的实际定义调整白名单。
2. 拒绝分类可复用 `EMPTY` 或新增（如 `EMPTY_CASE`）并补 `reason.cn` 映射
   （92-106 行那张表）。**跨页面用例不受影响**：它们 tap/input/assert
   至少出现一个。
3. 修复链路（`_validate_and_repair`，1189 行起）注意别把这条误当
   「可自动修复」的问题——空壳不是改改参数能救的，应直接拒。
