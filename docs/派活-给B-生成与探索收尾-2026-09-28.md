## 一、NL→用例的「断言目标选择」（真机实测抓到的生成质量缺陷）

**现场**（B8，deepseek-flash + 真机执行，`tools/_out/nl_eval/nl_eval.md`）：
两条正样本用例**各挂 1 步，根因相同**——模型把**导航前页面**的控件
（`tv_probe_always`，Index 页）写进了**导航后**（Second 页）的断言：

```
步1-4: start → waitFor(btn_go_second) → tap → waitIdle   ✅
步5:   assert exists id=tv_probe_always                   ❌ 控件在 Index，设备已在 Second
```

L3 步骤级 84.6%、**用例级 0/2**——不是引擎抖动，是断言生成策略缺陷。

**修法方向**（你定，给 C 过目）：断言生成时注入「动作序列的页面上下文」——
导航类动作（tap/swipe/back 之后）产生的断言，目标控件必须来自**导航后**
的页面快照；或至少对断言目标与当前页 `page_path` 做一致性校验
（`PageState.page_path` 已可用）。

**验收**：补离线钉子（构造「导航后断言导航前控件」的样本应被修正/拦截）；

start/tap/input/swipe/back/waitFor/assert——
`double_tap/long_press/fling/screenshot/home/key` 的留痕被**静默丢弃**，

**现状**：`generator.py` 的 `_validate_and_repair`（~1280 行）拿到

`repair_notes` 写明「断言语义需真机验证」。离线钉子：
start→tap→assert 三步 + driver 的用例，校验结果不再是 DRYRUN_FAILED。
