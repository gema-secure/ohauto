## 一、项目定位

**面向 OpenHarmony 的多模态智能 UI 自动化测试系统**——只依赖 `hdc` 命令行（设备侧**零部署**），
把「控件树、截图视觉、OCR、静态源码」四路信息**契约式融合**，做
定位 → 执行 → 失败归因 → 定位器自愈 → 用例生成的完整闭环，并覆盖折叠屏等**多形态**。

参赛：2026 开源鸿蒙大学生创新大赛 · 赛道一（10-31 提交）。
核心叙事：**树盲区靠多模态兜底、失败会自己归因、定位器会自己变好、懂鸿蒙多形态。**

## 四、功能清单（按能力域，全部列举）

1. **设备接入**：多设备 `-t` 路由、四级 hdc 查找、`--vision` 截图、锁屏自愈（唤醒+上滑）、
   校时、模拟器命令行化（自检/启动/快照）、形态档案（foldable/phone/tablet/2in1）。
2. **感知与定位（五级降链）**：L1 id 精确 → L2 id 模糊+文案 → L3 父链类型路径 → L4 视觉 → L5 坐标兜底（记告警）。
3. **N 源融合**：静态源/控件树/视觉/OCR 四源适配器；`Claim(kind,value,scope)` 契约 +
   declaration/observation 角色；**降级一等公民**（源不可用必须 `ok=False+原因`）。
4. **执行引擎**：Action DSL（start/tap/input/swipe/fling/back/home/waitFor/waitGone/waitIdle/assert/screenshot）、
   步骤级重试与退避、级联失败识别、设备心跳与连接级恢复、批量编排（`--repeat`）、
   报告（json/md/html）、截图留痕、崩溃信号采集（faultlogger）。
5. **失败归因**：四分类（定位失败/应用缺陷/环境问题/用例问题）+ 信号交叉印证 + 定位器回写。
6. **自愈**：连续失败计数 → 阈值触发 → 重探索换代（五档线索：control_key / 子树文案 / 自带文案 /
   池剩一 / **视觉换通道**）→ 验证 → 提交或**真回滚**（快照含全部线索字段）。
7. **生成**：自然语言 → 测试点 → DSL（两阶段，预取并发）；静态校验（空壳闸/坐标红线/DSL 合法/
   控件存在性按页并集）；确定性修复 + LLM 修复轮。
8. **跨形态**：双态/四形态差异比对、四类差异判据（缺失/溢出/…）、根因聚类（77 条→2 根因）、
   影响定级、修复回归门禁、报告渲染。
9. **评测工装**：离线 KPI 全量、NL 生成真机评测（多页）、视觉评测（两批 46 项）、
   视觉缓存命中率、探索覆盖率（页级）、延迟分段测量、长稳与趋势、降级链真机树验证、
   闭环演示一键重放、视频粗剪合成、画廊/一页纸演示页生成、质量门禁一键全绿。
10. **工程底座**：静态检查（零依赖三闸：T101/NAR001/CONV2）、质量门禁（5 关）、
    1361 项测试、Git 干线（10-08 当日 12+ 提交）。

### 5.1 KPI 层

1. **B6 端到端 ≤200ms：❌，且按平台边界永远达不到**。
   追根溯源：200ms 出自 `项目规划.md` §三**自定目标**（同表给视觉留 2s），且原始口径是
   「**单步耗时**」而非「定位全链延迟」—— 名字在流传中漂移了。真机硬底：`dumpLayout`
   一次往返 ~1030ms（`echo` 152ms 证明通道不慢、`-i` 无差证明不是过滤在算）。
   **已做**：口径拆两行（宿主侧 10ms ✅）/ 树复用+合并往返（−26%）。
   **已明确不做**：换 ArkTS API 通路（快但要装测试 HAP，丢「零部署」卖点）。
   **可选后续**：waitIdle 的签名轮询改事件驱动（语义上目前不能缓存）。
2. ~~**B8 的 L2 ≥80%**：本轮 1/3（1 条正样本 ✅ + 2 条固定负样本）~~ → ✅ **10-08 晚已收口**：
   样本补到规划要求的口径（**24 条正样本 + 2 条固定负样本**；正样本 = 19 条真机树自动派生
   + 5 条人工补充多步描述，见 `tools/b8_prompts_calc.txt`），
   **L2 可执行 24/26 = 92.3%**（可执行的 24 条**全部真引用控件/断言，空壳 0**；**两轮复跑一致**），
   两条负样本被空壳闸与测试点闸分别拦下；**L3 真机两轮并列：用例级 23/24 = 95.8% 与 22/24 = 91.7%、
   步骤级 176/177 = 99.4% 与 170/172 = 98.8%**。
   两轮挂掉的两条**同属「断言/期望落在控件树之外」**：① 「C 清零后断言显示为 0」——
   真机实测计算器 `id=result` **视觉是 0、控件树里是空串**，属**应用侧可访问性缺口**；
   ② 「点击 /」—— 模型自己加断言 `expression == "/"`，而计算器**忽略前导运算符**
   （冷启动按 `/` 后 `expression` 仍是 `''`），属模型波动/生成质量类。**都不是机制问题**。
   口径与五条局限（单应用单设备、19+5 配比偏斜、负样本只 2 条、断言集中在"显示值"、key 待轮换）见
   `docs/B8-20样本真机评测-2026-10-08.md`。**待做**：再跑几轮取稳定值 + 负样本扩样。
3. **「标准控件定位准确率 ≥95%」（规划 §三第一条）**：实测口径是「与控件树标注的**一致性**」
   94.7%/95.0%，**不是绝对准确率**（没有人工真值标注集）。对外必须按已声明口径讲。
